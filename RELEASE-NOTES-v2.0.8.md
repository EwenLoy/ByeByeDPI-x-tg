- **«Выключить TLS для CF-прокси и CF-worker» теперь включён по умолчанию.** Соединения к Cloudflare идут на 80-й порт вместо TLS 443 — на сетях, где DPI режет TLS Handshake, это заметно устойчивее
- Если раньше всё работало, а с этим параметром стало хуже — выключите его: «Настройки TG WS Proxy» → «Логи и производительность». Если наоборот — рвалось по TLS — оставьте включённым. Тумблер работает в обе стороны, ничего больше настраивать не нужно
- Отдельный экран «Настройки TG WS Proxy» вместо трёх пунктов на главном: секрет MTProto, датацентры, Cloudflare Proxy, Cloudflare Worker, Fake TLS, логи и дополнительные параметры
- DC-адреса редактируются по каждому датацентру отдельно (DC1–DC4, а в экспериментальном режиме ещё DC5, DC203 и media-датацентры) — раньше этой настройки не было в интерфейсе
- Список DC-адресов уходит в ядро и при включённом Cloudflare: свои IP теперь учитываются и в прямом маршруте, а не только при выключенном CF
- Cloudflare Worker: список своих `*.workers.dev` доменов через запятую — бесплатный обход через Cloudflare, когда CF-прокси недоступен
- Fake TLS: домен для маскировки SNI под реальный сайт. Пусто — выключено
- PROXY protocol v1: ядро принимает реальный IP клиента, если перед ним стоит свой прокси
- Размер буфера TCP-сокета (SO_RCVBUF/SO_SNDBUF) выбирается из списка 64 KB … 1 MB, по умолчанию 256 KB
- Тестовые DC: весь трафик идёт на тестовые датацентры — для диагностики, когда не понятно, чья сторона виновата
- Подробное логирование (verbose): отладочные сообщения в logcat и в файл лога
- Настройки применяются на лету — ядро перезапускается само, перезапускать приложение не нужно
- Очистка логов подчищает и файлы ядра (`tgws-native.log`, `tgws-native.1.log`), в логе не остаётся старых записей
